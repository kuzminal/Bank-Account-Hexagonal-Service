# 0002. Персистентность: Spring Data JPA + PostgreSQL

- **Статус:** Accepted
- **Дата:** 2025-09-23

## Контекст

Нужно долговременное хранение счетов с конкурентным доступом и транзакциями.
Рассматривались варианты: Spring Data JDBC, Spring Data JPA и R2DBC.

## Решение

Выбрали **Spring Data JPA + PostgreSQL 17** (пул соединений HikariCP).

Порт `BankAccountRepositoryPort` изолирует домен от конкретной реализации:
в основном окружении работает JPA-репозиторий, для демонстрации и тестов —
In-Memory реализация за тем же портом.

## Последствия

**Плюсы:**
- быстрая разработка и богатая экосистема Spring Data;
- транзакции и маппинг «из коробки»;
- порт позволяет подменять реализацию без правок домена.

**Минусы:**
- ORM-маппинг может «протекать» в домен (JPA-аннотации на сущности).
  Планируется вынести persistence-модель в `infrastructure`, оставив домен чистым;
- риск N+1 и ленивых загрузок — требуется контроль при росте модели.
